# راهنمای استقرار مِترا روی Netlify

این برنامه Next.js با App Router، مسیرهای API، رندر سمت سرور و PostgreSQL است. استقرار استاتیک (`next export`)، قرار دادن خروجی در `out`، و rewrite همه مسیرها به `index.html` برای آن درست نیست. فایل `netlify.toml` دستور ساخت، `.next` و Node.js 22 را مشخص می‌کند. Netlify آداپتر Next.js را به‌طور خودکار انتخاب می‌کند؛ نسخه آداپتر عمداً در پروژه پین نشده است.

## ۱. پایگاه‌داده و مهاجرت

1. یک PostgreSQL مدیریت‌شده با TLS، پشتیبان‌گیری و بازیابی آزمایش‌شده فراهم کنید. برای حجم serverless از pooler سازگار با تراکنش‌ها استفاده کنید؛ اتصال مستقیم پایگاه‌داده برای migration پیشنهاد می‌شود. محدودیت اتصال هر instance برنامه ۳ است، اما تعداد instanceها نامحدود نیست و باید متناسب با ظرفیت ارائه‌دهنده تنظیم و پایش شود. محل Functions و پایگاه‌داده را تا حد ممکن نزدیک انتخاب کنید؛ قابلیت انتخاب منطقه ممکن است به طرح حساب بستگی داشته باشد.
2. برای استقرار اولیه، روی پایگاه‌داده **خالی و اختصاصی**، با Node.js 22 و پس از `npm ci` دستور `npm run db:migrate` را اجرا کنید. متغیر `DIRECT_DATABASE_URL` در صورت وجود برای migration استفاده می‌شود، وگرنه `DATABASE_URL` استفاده می‌شود. اتصال migration باید دسترسی ساخت schema و جدول داشته باشد؛ مقدار آن را محرمانه و خارج از Git نگه دارید. فایل `drizzle/0000_initial.sql` و journal نسخه‌بندی‌شده هستند. اجرای دوباره migration روی پایگاه‌داده‌ای که همین migration را دریافت کرده بی‌اثر است.
3. **پایگاه‌داده موجود:** migration اولیه برای ساخت جداول از صفر است؛ آن را مستقیماً روی پایگاه‌داده‌ای که قبلاً با `drizzle-kit push` ساخته شده اجرا نکنید. از داده‌ها پشتیبان بگیرید و با متخصص PostgreSQL وضعیت و تاریخچه schema را تطبیق/به‌صورت امن baseline کنید؛ ابتدا روی کپی مستقل تمرین کنید. از `drizzle-kit push` یا اعمال migration در هر build تولیدی خودداری کنید. مهاجرت‌های بعدی را جداگانه تولید، بازبینی و در انتشار کنترل‌شده اجرا کنید.
4. برای Production و Deploy Preview/Branch Deploy پایگاه‌داده‌های جداگانه یا شاخه‌های ایزوله با داده آزمایشی استفاده کنید. استقرار preview نباید امکان تغییر داده تولیدی را داشته باشد. اگر این جداسازی وجود ندارد، preview را تا آماده شدن آن غیرفعال کنید.

## ۲. اتصال پروژه در Netlify

1. تغییرات شاخه را مطابق روند تیم در مخزن Git ثبت و به Git provider منتقل کنید، سپس پروژه را در داشبورد Netlify از همان مخزن متصل کنید. ساخت و انتشار را ابتدا روی Deploy Preview انجام دهید.
2. مقدار `DATABASE_URL` را در **Project configuration > Environment variables** با تنظیم جداگانه برای هر deploy context ثبت کنید. در صورت داشتن انتخاب scope، هر دو **Builds** و **Functions** لازم‌اند: در build، Next.js پیکربندی سرور را جمع‌آوری می‌کند و در زمان اجرا توابع به اتصال نیاز دارند. از درج رمز در `netlify.toml`، Git یا متغیر `NEXT_PUBLIC_*` خودداری کنید. پس از تغییر متغیر، redeploy لازم است.
3. `ARENA_PREVIEW` را در Netlify تنظیم نکنید: این متغیر فقط مخصوص قاب پیش‌نمایش Arena است و محدودیت قاب‌بندی و نوع کوکی را تغییر می‌دهد. `NETLIFY_NEXT_PLUGIN_SKIP`، تنظیمات static export و redirect عمومی به index را نیز فعال نکنید.
4. در صورت تنظیم دستی، Build command برابر `npm run build` و Publish directory برابر `.next` است. از تنظیم اشتباه `NODE_ENV=production` هنگام نصب وابستگی‌های build خودداری کنید؛ TypeScript و ابزارهای لازم build باید نصب شوند. هیچ توکن، پایگاه‌داده یا migration خودکاری در این مخزن قرار داده نشده است.

## ۳. کنترل پس از استقرار

- `GET /api/health` باید HTTP 200 و `{"ok":true}` بدهد. این کنترل وجود جدول‌های اصلی و اتصال DB را می‌سنجد، اما جایگزین ممیزی کامل schema یا تست عملکرد نیست.
- با مرورگر واقعی یک فضای کار بسازید، صفحه را بازخوانی کنید، پروژه و ردیف بسازید، ورود/خروج حساب و ایزوله‌بودن دو حساب را بررسی کنید. کوکی production باید `Secure`, `HttpOnly`, `SameSite=Lax` باشد. تطابق Origin، nonce اسکریپت‌ها، CSP و نمایش تصویر/PDF خصوصی را روی آدرس واقعی دامنه بررسی کنید.
- روی داده ساختگی، نسخه برآورد ایجاد کنید؛ JSON، CSV، XLSX، ریزمتره و چاپ/PDF را دانلود و در نرم‌افزار مقصد بازبینی کنید. حساب‌های آزمایشی و داده‌ها را پاک کنید. پس از تأیید preview و پشتیبان، انتشار production را انجام دهید و دوباره همین کنترل‌ها را تکرار کنید.

## محدودیت‌های مهم و تصمیم انتشار

- این آماده‌سازی **اثبات deploy واقعی نیست**؛ بدون سایت و پایگاه‌داده متصل کاربر نمی‌توان استقرار و endpoint عمومی را تأیید کرد. نسخه محلی Netlify CLI در حالت offline، build و بسته‌های Function و Edge Function را تولید کرد، اما به‌دلیل محدودیت شبکه نتوانست فایل type پیکربندی Edge را از `edge.netlify.com` بارگذاری کند و هشدار داد. در build واقعی Netlify باید لاگ بدون این خطا و عملکرد واقعی هر دو Function و Edge Function بررسی شوند.
- سقف عملیاتی محافظه‌کارانه اسناد ۳ MiB و فایل فهرست‌بها ۲٫۸ MB است؛ درخواست JSON حداکثر ۴ MiB است. این سقف‌ها برای سربار multipart/base64 و محدودیت payload توابع انتخاب شده‌اند. فایل‌های بزرگ‌تر باید به بخش‌های کوچک‌تر تقسیم شوند. خروجی‌ها و فضای کار بسیار بزرگ نیز تابع سقف پاسخ، زمان اجرا و حافظه Netlify هستند؛ بار و حداکثر حجم واقعی روی طرح و محیط مقصد باید سنجیده شود. برای مقیاس بزرگ به ذخیره‌سازی شیء و بارگذاری مستقیم/بخش‌بندی‌شده نیاز است.
- محدودیت تلاش ورود و ایجاد مهمان فعلی در حافظه هر پردازش است، در چند instance مشترک نیست و برای انتشار عمومی کافی نیست. قبل از دسترسی عمومی، rate limiting معتبر در لایه Netlify برای `/api/auth` و `/api/workspace` و سایر APIها، حفاظت بات/WAF، بودجه و پایش مصرف، TLS، پشتیبان‌گیری و بازیابی، سیاست نگهداری نشست/مهمان و آزمون نفوذ را تنظیم و در طرح حساب خود تأیید کنید. به هدر IP دلخواه کاربر به‌عنوان هویت قابل اعتماد اتکا نکنید. اسکن بدافزار برای اسناد نیز پیاده‌سازی نشده است.
- فهرست‌بها و ضوابط رسمی به‌صورت خودکار دریافت یا تأیید نمی‌شوند و خروجی‌ها آماده اتکای قراردادی بدون بررسی کارشناس نیستند. جزئیات در `docs/FINAL_AUDIT.md` آمده است.

### نشست در پیش‌نمایش Arena

فقط با `ARENA_PREVIEW=1`، اگر مرورگر کوکی partitioned را برنگرداند، برنامه نشست سروری را با یک توکن تصادفی در هدر درخواست‌های هم‌مبدأ منتقل می‌کند. توکن در `sessionStorage` همان برگه نگهداری می‌شود، در URL قرار نمی‌گیرد و در خروج باطل می‌شود. این روش برای iframe پیش‌نمایش است، نه انتشار عمومی: توکن برخلاف کوکی HttpOnly در دسترس JavaScript هم‌مبدأ است، بنابراین خطر XSS بیشتر است. این متغیر را در Netlify و محیط عمومی تنظیم نکنید؛ HTTPS و کوکی HttpOnly روش عادی هستند. در صورت مسدودبودن `sessionStorage`، نشست فقط تا پایان عمر صفحه در حافظه است و با بارگذاری مجدد از دست می‌رود؛ هشدار در صفحه نمایش داده می‌شود. برای بازیابی کار، پیش از ترک صفحه حساب ایجاد کنید. اطلاعات مهمان بدون نشست قابل بازیابی نیست. در نشست نامعتبر، ساخت فضای جدید فقط با تأیید کاربر انجام می‌شود.
